# DC-17 Engine: the numbers the build card and site rows show

No behaviour change. New exported functions, each replacing the logic it was cut out of (no copies).

## What changed
- `sites.ts`
  - `siteCapexParts(o)` -> `{ building, repeatSaving, extra, crash, rush, fastTrack, community, total }` ($B, whole
    campus). `siteCapex` is now `siteCapexParts(o).total`. [D] `total` is computed as GW x (per-GW sum, same order as
    before) so every capex is bit-identical to the old formula; the parts sum to it within 1e-12.
  - `oppositionParts(s, site)` -> `{ blockBase, delayBase, mood, crashMult, communityMult, block, delay }`. Rent: bases 0,
    factors 1. Reactive (E27) site: blockBase = 1 - unblock odds, factors 1, delay 0. `oppositionOdds` returns
    `{ block, delay }` from it.
  - `siteFit(o)`: building clamped to [100 MW, source cap], buildings = largest of 1/3/5 that is <= asked and fits the cap
    (rent 1). `newSite` now reads `levers(siteFit(o))`; its inline clamp is gone. [D] `siteFit` does not apply the rent
    lever-off rule (that stays `levers`, applied by the engine).
- `forecast.ts`: `siteBuildingsView(s, x)` -> `{ of, live, inConstruction, firm, buildings: { liveQ, buildFromQ?, live }[] }`
  (undefined when blocked). `live` = siteLiveMW(x, today) / building MW; `inConstruction` = buildings with buildFromQ <=
  today's quarter < liveQ; `buildFromQ` = liveQ - ws3.buildQ (rent: absent). [D] a start site's `buildFromQ` uses its
  stored ws3.buildQ (8), as siteBars does.
- `index.ts` (export lines): `oppositionLevel`, `oppositionParts`, `sitePermitQ`, `siteBuildQ`, `sitePowerQ`,
  `siteCapexParts`, `siteFit`, `siteBuildingsView` and types `CapexParts`, `OppositionParts`, `SiteBuildingsView`.
