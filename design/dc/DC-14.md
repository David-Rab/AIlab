# DC-14 Player bot builds campuses

## Rule (finance/plan.ts)
- **Gap sites (quarterly):** candidates = grid and gas x building size from `SITE_TIERS` (100 / 300 / 1000 MW) x
  buildings 1 / 3 / 5, dropping any that `siteSizeError` refuses (campus total over the source cap: grid <= 1 GW,
  gas <= 5 GW). Each candidate gets every lever that helps (as DC-7: crash, rush, fast-track kept only if each saves >= 1
  quarter on the first building given the others; community always). Of the candidates whose campus total covers the
  gap, the earliest *first-building* live quarter wins; a tie goes to the cheaper capex. [D] If the gap is bigger than any
  campus holds, the biggest campuses compete (same rule) and the loop continues with the rest.
- The old sizing `min(maxMW, max(500, gap))` is gone: the bot never sizes a building to the gap or the cap.
- **Rent:** as DC-7 (when short at `rentQ`, offBalance, shortfall >= 100 MW) but the hall is a tier size [D, designer
  correction]: the smallest tier covering the shortfall, else 1 GW. Before: the exact shortfall.
- **`mwBy`:** reads live capacity per building with `siteLiveMW` (live sites; sites under construction and, with
  `includePlanned`, sites in permits or waiting for power, from `siteBuildingLiveQs`, so a campus counts only the
  buildings live by that day). Replaces the `x.mw` reads and `siteLiveQ`.
- **`actions.ts` `siteOpts`:** one building = clamp to [SITE_MIN_MW, min(source cap, largest SITE_TIERS value)], the
  single entry point of cmp.newSite (preview and apply both read it). Start sites untouched.
- **`scripts/v2/finance.ts`:** the day-730 `liveMW` reads `siteLiveMW(x, day)` (plus its import).
